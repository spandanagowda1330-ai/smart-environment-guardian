# Contributing to Smart Environment Guardian

## Purpose

This document describes the basic contribution guidelines for the Smart Environment Guardian project.

## Team Guidelines

- Keep code and documentation organized in the appropriate folders.
- Follow the project requirements and agreed architecture.
- Do not commit passwords, API keys, or other confidential information.
- Do not mark tests as passed without performing them.
- Keep documentation updated when requirements or implementation details change.

## GitHub Workflow

1. Work on the files assigned to you.
2. Create a separate branch for significant changes when required by the team.
3. Commit changes with clear, meaningful commit messages.
4. Open a pull request when the team uses pull requests for review.
5. Review feedback and make the required corrections before merging.

## Testing and Evidence

- Record the tests that were actually performed.
- Include relevant build output, serial monitor logs, or hardware demonstration evidence.
- Link evidence to the appropriate test ID in `traceability-matrix.csv`.
- Clearly mark tests as Pending, Passed, or Failed based on verified results.

## Documentation Responsibilities

- Keep project requirements and architecture documentation current.
- Update implementation file references when source files become available.
- Maintain the test plan, acceptance test results, and traceability matrix.
- Confirm project-specific FirmGen procedures with the project lead.

## Current Project Status

The project is under development. Hardware integration, firmware verification, and acceptance testing must be documented as they occur.
